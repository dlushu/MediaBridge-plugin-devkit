# 源插件契约

通用模型（包、通道、动作、执行、缓存、webui）见 [plugin-contract.md](plugin-contract.md)；
本文只管 `source` 类型插件**额外**要遵守的：动作清单、组/站点模型、显示与定位口径。

---

## 一、动作总表

> 返回字段在面板与客户端上**长什么样、命名与定位有哪些硬性口径**（实例名 / 候选清洗 /
> 按季集定位 / 版本标签 / 发版自检表），见本文「二、显示与定位口径」。

| 动作（中文名） | 动作 id（代码里用的） | 入参 | 出参 | 必需性 |
|---|---|---|---|---|
| 站点清单 | `sites` | — | `{ sources, sites }`：组（源实例）一行一个（含运行态）+ 每组的站点数组（两级结构见下） | 必需 |
| 候选 | `search` | 实例 + 站点 key + 搜索词、页码、超时 | 候选列表（+ 上游响应原样） | **仅两层式站点** |
| 取播放项 | `detail` | 实例 + 站点 key + 条目 id + 集号/取法、超时 | 结构化 `detail`：线路 → 选集，每个播放项带 `ref` | 必需 |
| 解析地址 | `play` | `ref` + 客户端主机名、超时 | 真实可直连地址（`{urls, header, parse}`） | 必需 |
| 站点测速 | `probe` | 实例 + 站点 key + 搜索词、超时 | 一发探针的结果 | 必需 |
| webui | `http` | `{method, path, query, body, contentType}` | `{status?, body, contentType?}` | 可选 |

> **失败口径**（总契约第十节）：`source` 是"信封式"通道 —— 抛异常（带 `e.code`）**或**回一个带
> `error` 的对象都算失败；面板如实回失败码、如实留空，不编数据、不静默回退。

### `sites()` 的两级结构：组（`sources[]`）→ 站点（`sites[]`）

`站点清单` 一次回两组数组。**一个插件可以申报多个组，每个组下可以挂多个站点**，
都按插件自己设置页里的配置动态申报（接了几台外部服务，就可以报几个站）：

```js
{
  // 组（源实例）：一行一个
  sources: [{ id, name, url, mode, enabled, ok, ms, siteCount }],
  // 站点：一行一个，source 指明它归哪个组（取该组的 sources[].id）
  sites:   [{ key, name, api, searchable, source, directLines? }],
}
```

- `sources[].id` 是**组 id**（插件内唯一）。面板把它拼成 `插件 id/组 id` 作为这一组的全局身份；
  后续动作入参里的 `source` 就是这个**组 id**（`插件 id/` 那半段面板已用来把请求路由到本插件）。
- `sites[].source` 填所属组的 `id`，`key` 只要求**组内唯一**。面板取数一律按
  **`source`（组）+ `key`（站）** 两级定位，插件要按这两个参数找到对应那台外部服务的
  地址 / 凭据 / 令牌（各站各自独立，不许串）。
- **典型「一组多站」= Emby 片源**：插件固定申报一个组（`Emby`），组下**每台外部 Emby
  服务器各申报一个站**，站点名 = 用户给这台外部 Emby 起的名字（如「动漫」「4K 影库」）。
  反过来，需要隔离凭据组时，一个插件也可以申报多个 `sources`，每个组下再挂自己的站。

- **线路与选集的解析在插件里**（`$$$` / `#` / `$` 是猫爪源自己的约定；直查那类插件根本没有线路）：
  「取播放项」回来的就是面板要的结构，面板不再解析协议文本。**面板保留**的是"填 Emby DTO"那半件事
  （集名里的规格解析 → `MediaSource` / `MediaStreams`）。
- **播放项上可以多带「规格字段」**，面板读到就填进 Emby 的 `MediaSource`：`container` / `sizeBytes` /
  `width` / `height` / `videoCodec` / `videoProfile` / `bitDepth` / `frameRate` / `videoRange` /
  `audioCodec` / `channelLayout` / `channels` / `atmos` / `bitRate`（体积给**字节数**；视频编码用
  `h264` / `hevc` / `av1` 这类中立名；动态范围用 `DOVI` / `HDR10+` / `HDR10` / `HDR` / `HLG`）。
  **插件给的优先**：面板另外还会从集名里正则猜一份，只有插件没给的项才用猜的兜底 —— 所以知道就给，
  不知道就留空，别填占位值（`0` / `false` / 空串一律算"没给"）。
- **版本显示名由面板填好，出口插件直接读**：面板在聚合 `detail` 的每个**可播目标**上写一个
  `versionLabel`（`[体积] 站点标签 · 线路flag [· 变体标注] [· 项标注]`，与面板 Emby 层展示的版本行
  同一份规则）。出口插件拿它当版本条目的显示名即可，**不必自己再拼** —— 两边口径因此不会漂
  （见面板仓库 [ADR-0063](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0063-version-label-at-aggregate-output.md)）。
  它按**取法**写：剧集目标在 `line.target.versionLabel`，电影目标在各 `line.items[].versionLabel`；
  该目标没有它就退回自拼（老响应没有这个字段）。
- **每条线路可以带 `playVia`，声明"这条线路的地址要不要带鉴权头"**：

  | 值 | 含义 | 客户端怎么取 |
  |---|---|---|
  | `'client'`（**缺省**） | 地址**能裸用**：客户端直连即可起播 | 客户端拿 `ref` 走面板的流端点，由面板 302 到真实地址（回环地址由插件按 `clientHost` 换成客户端可达的域名） |
  | `'proxy'` | 地址**必须带一串鉴权头**才取得动（缺了就是 403/断流，头由源给） | 出口插件二选一：① 自己 `play` 取到 `{urls, header}` 并**把头交给客户端**（须宿主支持）；② 把这条线路交回面板的流端点、带上 `playVia=proxy`，由面板**代持头**中继（见面板仓库 [ADR-0042](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0042-auth-line-byte-relay.md)） |

  - **缺省就是 `client`**：不写等于声明"裸用可播"。**面板一律按标注执行，不做类型探测式的兜底** ——
    漏标成 `proxy` 由插件自负（客户端会拿不到头、播不了），标成 `client` 而实际要头同样自负。
  - **`proxy` 的语义是"缺了这串头就播不动"，不是"源顺手给了头"**：源回 `header` 里常有
    信息性的头（`Referer` / `Origin` / 页面 UA），缺了照样能播 —— 那种线路该标 `client`。
    判据只有一条：**这条线路不带头发出去，客户端能不能播**。标错两个方向都吃亏：
    漏标 `proxy` → 客户端拿不到头、播不了；把可裸用的标成 `proxy` → 白白让面板代持流量。
  - **它是声明性标注，不是探测结果**：`detail` 阶段还没有地址可测（地址要 `play` 才拿得到），
    所以这条只能由插件按自己对源的了解写死；一个插件内可以逐条线路不同。
  - **`.m3u8` 之类 HLS 清单**：`client` 线路一样裸用，但客户端不能直接 302（相对路径会失基），
    得走面板流端点的 **200 中继**（把清单里的相对地址补成绝对），依据见面板仓库
    [ADR-0040](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0040-hls-playlist-relay.md)。
  - **把线路交回面板时怎么声明**：面板流端点
    `GET {panel}/api/agg/stream?domain=&ref=&token=` 另认一个 `playVia` 参数（缺省 `client`）；
    出口插件按 `detail` 里那条线路的 `playVia` 原样带上即可。不带 = 面板按 `client` 落（302 / 清单中继）。
  - **面板自己的 Emby 客户端入口（`/api/emby/*`）也按这同一份 `playVia` 落法**，且**不需要插件多传什么**：
    面板拼版本列表时就把该线路的 `playVia` 编进了版本 Id（`MediaSourceId`，读的是 `detail.lines[].playVia`），
    起播时自己取回判档 —— `proxy` 线路在 Emby 里同样由面板**代持头中继**（非清单字节中继 / 清单子地址中继）。
    依据见面板仓库 [ADR-0044](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0044-emby-stream-playvia-relay.md)。
- **`ref` 的形状约定只有一层**：`<插件 id>/<插件自己定的东西>`。面板只按**第一段**路由，
  其余一个字都不解释 —— 它把 `ref` 原样存进 `MediaSourceId`，播放时原样交回来。
  本例（猫爪源）里面是 base64url 的 JSON：实例 / 站点 / 线路 / 条目 id / 集 id / 定位坐标。
- **`clientHost` 为什么要给插件**：本地部署的实例回的是**回环地址**（`127.0.0.1:<端口>`），
  对客户端毫无意义。插件拿它拼成 `http://<客户端访问用的域名>:<实例端口>/…` 再回去 ——
  这一步原来在面板（它当时还知道实例端口），`ref` 转交之后面板不知道了，所以跟着搬进插件。
- **`init` 是插件内部的事**（有的站不先 `POST /init` 就搜不出来）：`search` / `probe` 自己先兜一次，
  按「实例地址 + 站点」记住，并在返回里带 `initCalled` 供面板记日志（诊断用，不参与打分）。
- ⚠️ `站点清单` 里仍带 `url` / `port`，但**只为诊断显示**（插件自己的设置页）——
  面板不再用它们取数、也不再用它改写播放地址。

### 本站点的五个字段（面板只认这五个 + 它自己补的统计）

`source`（**`插件 id / 实例 id`**，站点身份的一半）/ `key` / `name` / `api` / `directLines`（可选）。

- `directLines`（布尔，**缺省 `false`**）声明这个站点的取数式样（判据见下一节）：
  - `true` = **一层式**：`search` 回来的候选**直接带线路**（播放项已内嵌在候选里），不用再取详情；
  - `false` / 不写 = **两层式**：候选不带线路，面板再拿候选去 `detail` 取播放项。
  - 面板按「search 结果里带不带线路」分类，不靠猜中间经过了几跳（磁力索引 → 种子清单、
    影片页 → 播放地址这类多跳，只要线路要等 `detail` 才有，就一律两层式）。
  - ⚠️ 这是**面板唯一认的式样信号**。适配器自己配置里的其他字段（如猫爪的 `filterable` /
    `indexs`）是插件内部实现，面板不解释、不依赖。

- **站点身份 = `插件 + 实例 + 站点 key`**：站点 key 只在各自实例内唯一，两个实例都有 `nodejs_muou`
  是常事。面板侧一律用 `插件id/实例id` 这一串当 `source`，所以跨插件也不会撞。
- `api` 只是**诊断显示**用的（插件设置页里那串前缀）；面板不再拿它拼请求。

- **站点数可以是 0**。报 0 个站点的插件在站点表与模板里不出现（等于用不到它）——
  想让自己的插件被用就申报站点，这是插件作者的选择，面板不强制。
- **站点测速**同时回答"通不通"与"快不快"。不另设"探测"动作。
  ⇒ 分工是：**站点清单 = 静态声明有哪些站点；站点测速 = 实测能不能用、多快**。
- **播放项就是"线路"**：**一个名字对应一个地址**。两类站点都遵守这个结构，
  直查那类也**可以有多条**线路。差别只在"怎么取到这些线路"（见下：一层式 / 两层式）。

### 候选行上的认证标 `vod_exact`（插件认准，面板直接采信）

候选行（`search` 回来的 `json.list[]`，macCMS 形状）**可以多带一个布尔字段 `vod_exact`**：

- **语义**：插件自己已经认准「这一条就是用户要的目标作品」，请求面板**不要再判名字**。
- **缺省**：不写 / 非 `true` = 不认证，面板照旧走它那套打分（`match.js`）。
- **面板怎么采信**：见到 `vod_exact === true` 就把这条的分数**直接记 1**，其余一切不变
  （仍受分数线、`maxItems` 约束；只因分数最高，会排在最前、优先被取详情）。
- **只在两层式站点有意义**：认证标在候选行上，一层式站点不经过 `search → 判分`，用不上。

**这是插件的「声明性标注」，不是把判据搬进插件**：`vod_exact` 只在**这一条候选**上生效，
面板仍是「这是不是目标作品」的唯一判据实现（`match.js`），也仍对没有认证标的候选照常打分。
所以它与上一节「打分与过滤留在面板、不搬进插件」不冲突（理由见面板仓库
[ADR-0059](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0059-source-certified-candidate.md)）。

**什么时候该标**：插件对自己的检索结果有**确定性把握**时。典型是**番号站**——
搜索词本身是番号（`SSIS-001`），插件已按番号把候选过滤到「同一番号」这一条，天然满足"认准"。
⚠️ 别拿它当"提高分数"的顺手工具：标错了就是**误认**，会把不对的片子硬塞给用户
（面板不再用名字兜底拦截）。拿不准就别标，交给面板打分。

### 取数式样：一层式与两层式

**聚合的粒度是"版本"，不是"站点"**：对某一部片的某一集（一个元数据坐标），面板只做一件事 ——
向所有该域的站点询问"这一集有哪些可播线路"，能给出的各算一个版本，都不能给就如实空。

| 式样 | 链路 | 面板在中间做什么 | 适合 | 站点申报 |
|---|---|---|---|---|
| **两层式** | 给词 → 候选列表 →（面板打分 / 过滤）→ 取播放项 | 打分与过滤 | 聚合站那类（返回的是候选，不挑就会拿错同名片）；磁力索引、影片页类（线路要再取一次才有） | `directLines: false` 或缺省 |
| **一层式** | 给词 → 直接回播放项列表 | 不做筛选（站点自己保证取准） | 直查那类（给关键词就出地址） | `directLines: true` |

**打分与过滤留在面板、不搬进插件**（理由见 [ADR-0033](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0033-template-and-domain.md) 的说明）：
它是**跨来源统一的判据**（`match.js` 是"这是不是目标作品"的唯一实现），搬进插件会让判据分叉。
其参数跟着**模板**走。

⚠️ 其中只有一部分参数对**一层式**站点有意义（它们不做筛选）⇒ 设置页要写清
"哪些参数只对两层式站点生效"，免得出现"调了没反应"。

### 直绑元数据域条目 Id（`binds`）

面板按名搜（`search` → 打分）是**通用兜底**，但有些站点的**搜索精度很差**（典型：Pornhub ——
实测对任意查询都回一批泛化结果，首条从不是目标作品），按名搜必然命中 0，条目永远拿不到线路。
`binds` 给源插件一条**按 id 直连**的通道：插件声明「我认领某个元数据域的条目 Id」，面板据此
把该域条目的 entryId **直接交给本插件 `detail`**，跳过按名搜索。

**声明位置**：`plugin.json` 的 `binds`（域 id 数组，形状同 `domain`；见 [plugin-contract.md](plugin-contract.md) 字段表）。
例：`"binds": ["pornhub"]`＝本源插件的**每个站点**都能直接吃下 `pornhub` 域条目 Id 里的 entryId。

**面板取数优先级（契约规定，不是面板自由发挥）**：

1. **先直绑**：面板从条目 Id 解出域 + entryId，对**所有声明了该域 `binds` 的源插件**以
   `detail({ id: <entryId> })` 传入（entryId 由面板按域名解出后**原样**传入，见 `contract-metadata.md`
   「条目 Id」——坐标编解码不下放给插件）。**多个**源插件同时声明同一域 ⇒ **都试**，各自算一个版本
   （与「聚合的粒度是版本」一致）。
2. **直绑成功即用**：`detail` 回了可用线路时**不再执行该插件的按名搜索**（省一发扇出）。
3. **直绑失败 ⇒ 回落按名搜索（契约义务）**：`detail` **失败（抛错 / 回 `error` / `target` 为 `null` /
   `items` 为空）** 时，面板**必须回落**到该插件原有的 `search` → 打分路径。回落路径的判据、
   分数线、`maxItems`、`maxSources` 等一切不变（仍归 `match.js` / 模板）。
   - 回落是**契约义务**，面板**不得**因"声明了 `binds`"就只走直绑、失败即放弃。
   - 直绑与按名搜索**只对同一个插件二选一执行**，不双算。
   - 仅当**条目 Id 解不出域 / entryId** 时，面板**跳过直绑**、直接走该插件的按名搜索（没坐标可直传）。

**`vod_id` 回传口径（面板不解释、原样记入绑定）**：

- 直绑调用 `detail` 时，插件须在出参里回一个 **`vod_id`**（资源级坐标）作为绑定坐标的回传。
  `vod_id` 形状由插件自定（面板不解释）：通常就是该站自己的资源编号（如 Pornhub 的 viewkey）；
  若源站的候选行本就带 `vod_id`（macCMS 形状），沿用同一个值即可。
- 面板**不解释 `vod_id` 的语法、不校验它是否等于 entryId、不做形状判断、不反查**——把它**原样**记入
  `ProviderIds`（键为本元数据域，值即 `vod_id`）并编进播放 `ref`。**插件给什么就记什么**。
- 因此插件必须保证 `vod_id` **稳定、可在后续 `play` 阶段复用**；给错就是绑错（比不声明更糟）。
- **落点**：`detail` 出参的**资源级**（`detail.vod_id`），不是逐线路 / 逐项——同一资源无论多少版本、
  多少清晰度，都共享同一个 `vod_id`。

**⚠️ 声明即承诺**：`binds` 是插件对上游的**乐观声明**（同 `vod_exact` 性质的"声明性标注"）。
面板见到声明就**无条件**先直绑，**拿不准就别声明**——虽然失败会回落（不至更差），但声明了却常失败
会白烧一发直绑扇出。**别拿它当"提高命中"的顺手工具**。

**与「打分与过滤留在面板」的关系**：`binds` 不搬判据进插件——直绑时插件只负责"按 entryId 取自身
线路"，"这是不是目标作品"由**条目 Id 本身**锚定（元数据域已确认），面板不再打分。回落路径仍走面板打分。

## 二、显示与定位口径

# 源插件显示与定位规范

> 这份文件规定「源插件 `search` / `detail` 返回的数据，会怎样出现在聚合诊断页和 Emby 客户端上」。
> 改这两个动作的返回结构之前先看它——每一条都踩过线上的坑。
> 动作清单见本文「一、动作总表」；通道、鉴权、打包等通用约定见 [plugin-contract.md](plugin-contract.md)。

---

### 组名 = 源实例名 · 站点名（`·` 只由渲染层插入）

聚合页每个站点分组的绿色标题，渲染规则固定为：

```
sources[].name · sites[].name        // 例：PikPak 磁力 · BTSearch 磁力
```

**分隔符规则（踩过坑，别破坏）**：

- `·`（含 ` · `）是**渲染层专用分隔符**——标题里各字段之间的那一个，由聚合页 / Emby 渲染时代码插入。
- 数据字段（`sources[].name`、`sites[].name`、`line.flag`）必须是**单段文本，自身不许包含 `·`**：
  插件先拼好「A · B」，渲染层再拼一次，就会出现嵌套与归属错位（实测：`小雅 Alist · 综合内容 · 小雅 · 42.4GB`）。
- **站点是什么内容（综合 / 成人）不写进站点名**：内容分类只在**插件自己的设置页 / 网页**上展示
  （pikpak 设置页里的「Sukebei（成人内容）」「BTSearch（综合内容）」），`sites[].name` 只给站点本身的名字。
- 源实例名只能写实例自己。

`sites()` 申报的两组字段：

| 字段 | 写什么 | 例 |
| --- | --- | --- |
| `sources[].id/name/url` | 组（源实例）本身 | `pikpak` / `PikPak 磁力` |
| `sites[].key/name` | 组下面的各个站，单段名字，`sites[].source` 指向所属组的 `id` | `btsearch` / `BTSearch 磁力` |

#### 层级先搞清楚：插件 → 组（`sources[]`）→ 站点（`sites[]`）

- **一个片源插件可以申报多个组，每组下面可以申报多个站点**；组与站点都是**动态**的 ——
  插件按设置页里接入的外部服务申报，接了几台就报几个，不是「一个插件只能有一个组 / 一个站」。
- 站点用 `sites[].source`（= 所属组的 `sources[].id`）挂到组下；面板所有取数动作
  （`search` / `detail` / `probe`）都按 **`source`（组）+ `key`（站）** 两级坐标路由，
  插件要按这两个参数找到对应那台外部服务的连接信息与凭据（各站的凭据 / 令牌 / 缓存各自独立）。
- **Emby 片源走「一组多站」**：插件固定申报**一个组**（组名 `Emby`），组下**每台外部 Emby
  服务器各申报一个站点** —— 站点名就是用户给这台外部 Emby 起的名字（如「动漫」「4K 影库」），
  分组头相应显示成 `Emby · 动漫`、`Emby · 4K 影库`。

### 搜索候选（`search` → `json.list[]`）

面板只读四个字段：`vod_id`、`vod_name`、`vod_pic`、`vod_remarks`；外加一个**可选的**认证标
`vod_exact`（布尔，插件认准这条就是目标作品时写 `true`，面板直接采信、不再判名字，
契约见本文「一、动作总表」里的「候选行上的认证标」）。

#### 1. `vod_name` 必须是干净的片名主干

面板按 LCS 相似度给候选打分（名字占 0.7，硬闸门相似度 < 0.5 直接拒）。磁力站标题普遍是
「【高清剧集网发布 www.DDHDTV.com】 三体 第一季[杜比视界][全8集].2024.2160p…」这种形态，
主干被广告标签淹没就会**整批硬拒、0 分**。清洗是插件的活，必须在插件侧做（实现见 pikpak 的 `lib/title.js`）：

- 剥广告括号 / 裸域名 / 宣传语、行首发布组方括号、纯规格括号、年份与画质之后的整段场景尾巴；
- 保留集数话术（全30集 / 第一季 / 更211集）、剧场版、番号；删空了回退原名。

原始标题不要丢：塞进 `vod_id` 编码体里（pikpak 的 `rt` 字段），读分辨率/编码规格、
按种子内英文文件名挑正片都靠它。

| 原始标题（站点给的） | vod_name（交给面板的） |
| --- | --- |
| `【高清剧集网发布 www.DDHDTV.com】 三体 第一季[杜比视界版本][全8集]…2024.2160p…` | `三体 第一季全8集` |
| `[DBD-Raws][让子弹飞][1080P]…x264…` | `让子弹飞` |
| `SSIS-001 一ヶ月間の禁欲… 1080p` | `SSIS-001 一ヶ月間の禁欲…`（番号必须留） |

#### 2. `vod_remarks` 是一行短规格

写体积 / 做种或热度（`33.15 GB · H:35`），**不写广告词**。封面给不出就留空串，不要编。

封面（`vod_pic`）按总契约的三种形态给：完整 http(s) URL、面板代取 `/api/emby/img/{host}/{path}`、或"图床相对路径 + 该域申报的 `imageBase`"（见元数据契约的「图片基地址申报」）。**不要**写面板自己的实例地址。

### 详情必须按季集定位（`detail`）

面板**不做定位**，只把客户端请求的 `season` / `episode` 原样转进 `detail`。
插件返回的每条线路 `line.target` 必须就是「那一集」；规则与实现见 pikpak 的 `lib/locate.js`。

#### 两种取法（由入参 `pick` 区分）

| 场景 | 入参 | 线路里给什么 | `target` |
| --- | --- | --- | --- |
| 电影 | `pick: 'items'` | `items[]`：每个压制版本一项 | `items[0]`，每项各成一个客户端版本 |
| 剧集 | 无 pick | `episodes[]`：全集清单 | **按季集号定位到的那一项**，定位不到给 `null` |

`target` 为 `null` 的线路不会进客户端版本列表——这是正确行为：
**包里没有这一集时宁可不出这个版本，也不许拿列表第一项顶替**。
但前提是 `episodes` 必须**真的是全集**——见下面「必须回全集」。

#### 必须回全集：种子清单路不许截断播放项

detail 的剧集路里，`episodes` 必须包含这个资源的**全部正片视频**。
文件清单来自 `.torrent` / 站点详情接口（一次拿全）时，多回播放项**不多发任何请求**
（播放时才单独解析用户点中的那一集），所以任何「最多回 N 个」的截断都是错的：
截断后面板按季集定位会把「**清单里没有**」误判成「**包里没有**」。实测事故：
30 集包只回排序前 8，客户端请 S1E9 时 16 条候选全部「0 条定位到」。

- 整季包判据：至少两个文件名带出集号（`S01E09` / `第9集` / 行首裸编号）→ 带集号的视频全收；
- 关键词一个都不命中时（中文裸编号文件名 `09.2160p.HEVC…`）**不许退回「取体积最大的一个」**，
  多视频文件要全收；
- 播放项按季号 → 集号 → 文件名排序，让界面顺序与 `index` 稳定；
- 「最多回 N 个」只允许留在**真有逐文件请求成本**的路（逐个翻网盘目录的老路）。
- detailNote 里三个数要分开报：「共 N 个文件，其中 V 个视频，列出 I 个播放项」——
  把「挑出的条数」说成「视频数」会直接误导排查。

#### 剧集三级定位规则（命中后把依据写进 `target.matchedBy`）

1. **`title`**：集名明确写了「第X季第Y集」「SxxEyy」且季集完全匹配（季优先）；
2. **`episode`**：上一步没中 → 只写了集号的（第3集 / 03集 / 行首裸编号 / `E<数字>` 前缀），**任何季都认**
   （年番在源里是扁平编号 01~211，在 TMDB 可能算第 5 季）；
3. **`number`**：**仅当标题里解析不出任何季集号时**适用——剔掉方括号段、`SxxExx`、第X季、体积标注后，
   剩下的第一个**独立数字**等于集号。已写明季集号的条目（`SxxEyy`/`第X季第Y集`）不走上一步之外的第 3 级兜底，
   否则剧名里的数字会被当成集号：`小闲闲2.S02E01` 请 S1E2 会被错配到 `S02E01`（实测事故）。

三级都不中 → `null`，不猜。

集号解析的坑（都来自实测文件名）：

- 规格数字不是集号：`2160p`、`4K`、`x264`、`.mp4` 里的 4（两侧紧邻字母的数字排除）；
- 声道小数不是集号：`AAC5.1` / `DD5.1`；
- `E<数字>` 前缀是集号：`[1.4GB]E161.mp4【XIANNI2026】` 里的 **161 是集号**（花卷等源用「E+集号」命名）；
  但只认**前面不是字母**的 E —— `HEVC` / `MPEG4` / `EAC3` 这类词里的 E 后面即便跟数字也不算集号；
- 但 `30.2160p.HEVC…mp4` 里的 **30 是集号**（点后紧跟分辨率不算小数）；
- `斗破苍穹年番.211.4K.mp4` 里的 **211 是集号**（`.4K` 不是小数尾）；
- `S05E210` 这种规范段里的 210 不能被第三级单独捞走（先剔 `SxxExx`）。

### 版本标签：flag 单段 + 结构化字段，渲染层保证标题可区分

Emby 客户端里每个版本的标题由渲染层**按固定顺序**拼成：

```
[本集大小] 站点名 · 线路名(flag) · 变体标签 · 电影规格标签
```

只有各字段之间的 ` · ` 是渲染层加的，字段内容全部单段。

- **站点名**：`sites[].name` 的完整值（猫爪站名自带 `片库|4K` 这类画质后缀，`|` 不是本契约说的分隔符，原样保留）。
- **线路名 `line.flag` = 单段稳定标识**：如 `夸克原画` / `PikPak` / `小雅`。
  - **前缀必须稳定**：模板的 `lineFilter` 按它命中（Tmdb 模板是 `夸克原画|^夸克$|百度原画|Pikpak|小雅`），改名前先 grep 模板里的过滤规则。
  - flag 自身**不带 `·`，不拼整包体积 / 分辨率 / 编码**——这些走播放项的结构化字段，由渲染层决定怎么显示。
- **同名候选靠结构化字段区分**：磁力候选经第二节清洗后全部同名（都叫「三体」），
  33GB 与 153GB 两个种子靠每集自己的 `sizeBytes`（标题前缀 `[xG]`）以及
  `height` / `videoCodec` 区分。渲染层保证**同一播放页不出现完全相同的标题**：
  撞名时按「分辨率 → 编码 → 第 N 版本」从结构化字段补一段；只在撞名时补，不撞不添噪。
- **变体标签**：面板只从候选 `vod_name` 的括号段取（`三体(臻彩)` → `臻彩`），插件没有别的入口。
- **集名前缀 `[xGB]`**：面板的规格兜底解析与诊断弹窗都认这种写法（猫爪集名同款，
  如 `[2.2GB]1-第1话….mp4`）。显示名加前缀即可，**ref 里必须保留原始文件名**
  （播放时要按原名回网盘对文件，两者不能混）。
- **规格字段**（`sizeBytes` / `width` / `height` / `videoCodec` / …）：有才给，
  `0` / 空串 / `false` 一律算「没给」——面板会拿集名再猜一遍兜底，填假值会把兜底挡掉。
  体积给每文件精确字节数（种子清单里有），分辨率/编码从发布标题读。
