# 字幕插件契约

通用模型（包、通道、动作、执行、缓存、webui）见 [plugin-contract.md](plugin-contract.md)；
本文只管 `subtitle` 类型插件**额外**要遵守的：申报轨、取内容、ref 与缓存。

---

## 一、动作总表


字幕插件（`subtitle`）为**聚合出来的播放目标**申报字幕轨，并在客户端点开某条轨时给出字幕内容。
它**不占端口、不接 Emby**，能力就两件事：**申报有哪些轨**、**给出某条轨的内容**。
面板把申报的轨接进 Emby 版本的 `MediaStreams`（`Type: 'Subtitle'` 的流），并暴露 Emby 标准的内容端点
`GET /Videos/{ItemId}/{MediaSourceId}/Subtitles/{Index}/Stream.{Format}` 让客户端取内容
（面板侧端点口径见面板仓库 `docs/emby-compat.md`）。

| 动作（中文名） | 动作 id | 入参 | 出参 | 必需性 |
|---|---|---|---|---|
| 申报字幕轨 | `tracks` | 播放目标的坐标 + 超时 | 字幕轨数组 `[{ lang, format, label?, ref }]` | 必需 |
| 取字幕内容 | `fetch` | `{ ref }` + 超时 | `{ body, contentType? }` | 必需 |

面板按自己的规则决定问哪些字幕插件（启用状态等）；插件只管按收到的坐标回轨，
不关心"外面还有几个字幕插件、它们给了什么"。

### `tracks`：申报哪些轨

- **返回一个数组**：一条字幕一种语言算一条。**多语言是契约能力** —— 一个插件可以报多条
  （不同语言 / 不同格式），只报一条同样合法；**报空数组** = 这个目标没有字幕可报（面板如实不填任何轨）。
- 每条轨的字段：

  | 字段 | 必填 | 说明 |
  |---|---|---|
  | `lang` | 是 | 语言码（BCP-47 / ISO 639 风格，如 `zh-CN` / `zh` / `en` / `ja`）。面板**原样**写进 `MediaStreams[].Language`，不翻译、不归一化 |
  | `format` | 是 | 内容格式，认 `srt` / `ass` / `ssa` / `vtt`（大小写不敏感）。面板据此填 `Codec`，也是内容端点地址里的后缀 |
  | `label` | — | 显示名（可选）；面板填进客户端看到的轨名，不写就按 `lang` 显示 |
  | `ref` | 是 | **这条轨自己的凭据**（见下） |

- **入参是"这一集的坐标"**，显式字段：`{ name, originalName, year, season, episode }` ——
  与面板按名字定位条目用的那套坐标同源（`name` 主标题、`originalName` 原名、`year` 年份、
  `season` / `episode` 季集号；原名 / 年份拿不到时是空串，电影没有季集号时 `season` / `episode` 为 `null`）。
  字幕插件据此判断"这一集有没有字幕"。它**不需要**知道走的是哪条线路 —— 字幕与线路无关。
- **面板为一个播放目标问一次 `tracks`**，把回来的轨挂到该目标的**每个版本**上；
  插件不必为每个版本各答一次，但 `tracks` 可能被重复调用，**要能重复答**。
- **`{Index}` 是这条轨在该版本 `MediaStreams` 里的流序号（`MediaStreams[].Index`）**，不是"字幕数组里第几条" ——
  面板把每条轨当作一条 `Type: 'Subtitle'` 的流追加进版本的 `MediaStreams`，序号在视频 / 音频流之后顺延。
  插件**不需要**关心 `Index` —— `fetch` 只认 `ref`。

### `ref`：字幕轨自己的凭据（不透明）

- **与源插件的 `ref` 同一套路**：形状 `<插件 id>/<插件自己定的东西>`。面板只按**第一段**路由
  （据此找到该问哪个插件），其余一个字都不解释。
- 面板把每条轨**连同它的 `ref`** 一起编进那个版本的 `MediaSourceId`；客户端点开某条轨时，
  面板从 `MediaSourceId` 解出这条轨的 `ref`，**原样**交回 `fetch({ ref })`。
  ⇒ **不需要重跑 `tracks` 按位置反查**。
- 只要内容还在，插件随时能把 `ref` 换成一个内容结果（**可重复解析是插件的义务**）；
  `ref` 的有效期与它背后的缓存都由插件自己管。

### `fetch`：给出某条轨的内容

- 入参就是 **`{ ref }`**（`tracks` 给的那条轨的凭据）。面板不往里塞别的东西，也不要求
  "按坐标重搜一遍" —— 插件认 `ref` 就够。
- 出参 `{ body, contentType? }`：`body` 是**字符串**（UTF-8 文本，SRT / ASS / VTT 都算）；
  `contentType` 不写就由面板按 `format` 落。
- **内容是什么，契约不管**：插件想给什么就给什么，面板**原样**交给客户端 —— 不二次判断、不加壳、
  不替换。取不到时怎么回由插件自己定：想"给一段说明性内容"就**正常 return**；想"如实报失败"就
  **`throw`**（带 `e.code`）—— ⚠️ 字幕桥把 `fetch` 的返回值**直接**当 `{ body, contentType? }` 用，
  **不认 `{ok:false,error}` 这种业务信封**，回那种对象会被当成"成功但没给内容"。口径见总契约第十节。

### `tracks` 允不允许联网？

- **契约不规定**：`tracks` 里要不要联网、联几次，是**插件的实现自由** —— 契约既不禁止也不要求。
  插件可以"就地申报"（不联网），也可以"先搜到再申报"（联网）。
- 但**面板要按最坏情况记账**：若插件在 `tracks` 里联网，那"打开条目详情 / 列出版本"这一步就可能
  产生上游请求（扇出落在**声明阶段**）；不联网的插件则声明阶段 0 上游。这条是**面板侧的扇出账**，
  不是对插件的限制。

### 缓存与设置

- **字幕内容的缓存归插件自己**（与总契约第八节"插件侧的取数结果由插件自己缓存"一致）：同一个目标的
  `tracks` / `fetch` 会被面板与客户端反复要到，插件应当自己缓存，把常见查询做到秒回。
- **面板侧不为字幕另开缓存**：面板侧那份只装"这一条目的线路结果"，不含字幕字段，契约也不要求它含
  （见总契约第八节）。
- **语言 / 基地址等等是插件自己的配置**，由插件在自己的设置页声明、存进自己的 `data/`；
  **不是契约字段**。设置页本身按总契约第九节注册：在 `plugin.json` 写 `webui`（单类型包写
  `"webui": "ui/index.html"`），面板就在**「字幕」栏**下挂一个入口；页面的读写走 `http` 动作。
  契约只要求 `tracks` 能返回多条轨（多语言能力），插件这次只输出一种语言完全合法。
